토요일·주말 근무, 시간·통근·급여·계약 차이는 선택 가능한 특이사항으로 표시한다. 업무/급여 장점과 차이를 함께 설명하고 `specialNotes` 배열을 사용한다. 영업·외근·생산 중심 제외는 유지한다. 조사 로그와 갱신 통계는 별도 조사 기록 탭에 보관하며 메인에는 공고부터 보인다.

예시 검색어: 평택 사무보조, 동삭동 원무, 고덕 행정, 합정동 사무, 진위 수발주, 원곡 사무, 교육행정, 주문지원, 급여 협의, 회사 내규. 급여 하한 필터 없이 검색하는 회차도 포함한다. 검색 결과의 상대적 D-day보다 원문의 절대 마감일과 실제 마감 표시를 우선한다. 접속 제한·캐시 결과·목록만 확인한 경우 그 범위를 기록한다. 전체 사이트 전수 확인이라고 주장하지 않는다.

## 매번 갱신하는 절차

1. 최신 main과 작업 상태를 확인하고 위 출처에서 기존 ID의 모집 상태, 신규 공고와 조건 변경을 조사한다. 동일 회사·직무·근무지 중복을 통합한다.
2. 회사/실제 고용주/배치 사업장, 직원 수의 기준, 업무, 시간, 요일, 고용형태, 급여, 복지, 주소, 마감, 원문 URL을 확인한다. 모르는 값은 미확인으로 표시한다.
3. 기존 `JOBS` 항목은 삭제하지 않는다. 마감은 `recruitment:'마감'`, 삭제가 확인되면 `'원문 삭제'`, 확인 실패는 `'확인 필요'`. 기준 제외는 `outOfScope:true`. 회사 목록과 원문이 충돌하면 단정하지 말고 충돌 근거를 남긴다.
4. 새 공고만 안정적인 새 ID와 `addedBatch`를 부여한다. 기존 ID를 변경하거나 재발견을 신규 처리하지 않는다.
5. `salaryType`은 `negotiable`, `company-policy`, `undisclosed`. 금액이 명시돼 있어도 실제 협의 가능이면 해당 타입을 사용할 수 있다. 원문에 없는 협의 가능성을 만들어내지 않는다.
6. `JOB_UPDATE.id`는 실제 조사 완료 KST ISO 시각. `newIds`, `changedIds`, `closedIds`를 해당 배치 공고 ID 배열로 갱신한다. 조건 보완과 회사의 실제 조건 변경을 구분해 설명한다. `checkedAt`/`status`는 확인 성공인지 시도 실패인지 명확히 한다.
7. `index.html` 자료 시각과 최근 검색 결과를 맞춘다. 이전 조사 로그는 날짜를 붙여 보존한다. 제외·보류 이유와 확인 실패를 기록한다. 신규·조건 변경·마감·탭별 건수는 실제 데이터와 대조한다.
8. 변경한 정적 파일의 캐시 버전(`?v=`)을 올린다. UI/문서만 바꾸는 경우 자료 조사 시각은 그대로 둔다.
9. JS 문법, 공고 ID 중복, 필수 필드, 원문 링크, 급여 분류, 기존 기록 병합을 확인한다. 모바일 화면에서 신규 라벨, 탭/필터, 접기/펼치기, 홈 이동과 가로 넘침을 점검한다.
10. 변경 파일만 커밋·푸시한다. GitHub Pages 배포 후 공개 `index.html`/`jobs.js` 등이 로컬과 일치하는지, 브라우저에서 정상 렌더링되는지 확인한다. 푸시 성공만으로 배포 완료라고 말하지 않는다.

## 개인 기록과 화면 동작

- `localStorage` 키 `next-job-records-v2`를 유지한다. 구 키 `next-job-saved`의 마이그레이션도 유지한다.
- 관심·메모·진행 상태·최초 수집일·변경 이력은 같은 공고 ID로 병합한다. 검색에서 사라져도 마지막 스냅샷을 보존한다.
- 관심 기록은 같은 브라우저·같은 주소에만 남는다. GitHub 푸시는 사용자 기록을 동기화하지 않는다. 아내분은 같은 휴대폰 브라우저와 공개 주소를 사용한다. 데이터 삭제/기기 변경 전 백업·가져오기 기능을 사용한다.
- 현재 후보는 급여 협의 공고를 제외한 유효 후보. 급여 협의는 해당 타입의 유효 후보. 누적은 마감·제외 포함 전체. 관심은 저장한 공고이며 상태와 무관하게 보존한다.
- 제목은 클릭되지 않는 일반 텍스트. 옆의 홈 버튼 클릭: 현재 후보, 검색어 빈 값, 전체 필터, 모두 접힘, 맨 위. 개인 기록은 변경하지 않는다.
- 공고 복사는 회사·직무·급여·시간·지역·상태·원문 링크만 포함한다. 개인 메모·집 주소는 넣지 않는다.
- 네이버 출발지는 기기별 로컬 저장. `NAVER_DESTINATIONS`가 있는 공고는 자동차 경로, 없는 신규 목적지는 주소 검색으로 연다. 좌표 토큰을 추측하지 않는다. 실측 전 거리·시간을 수치화하지 않는다.

## 다른 PC에서 이어가기

회사 PC에서 GitHub 계정과 해당 저장소 쓰기 권한을 연결한다. 처음이면 다음 저장소를 원하는 작업 폴더에 clone하고 그 폴더를 Codex 작업 대상으로 연다.

```sh
git clone https://github.com/interojo-160907/jjanggu-job-dashboard.git
cd jjanggu-job-dashboard
git status --short
git remote -v
```

이미 clone했다면 작업 변경을 확인한 뒤 깨끗한 작업 트리에서 `git pull --ff-only origin main`. 집과 회사에서 동시에 수정하지 않는다. 충돌 시 기존 변경을 확인해 병합하며 reset/force push로 지우지 않는다. 인증 토큰을 문서나 저장소에 쓰지 않는다.

로컬 확인은 저장소에서 `python -m http.server 8765 --bind 127.0.0.1` 등 정적 서버를 사용한다. 임시 서버/개인 파일을 공개 저장소에 추가하지 않는다. 로컬·공개 주소는 개인 기록 저장 영역이 서로 다르다.
