# 짱구 박사 개인 대시보드

평택 인근 고정 근무·비영업 일자리를 검토하는 모바일 정적 대시보드입니다.

다른 PC에서 이어갈 때는 [작업 지침](AGENTS.md)과 [검색·갱신 인계서](docs/OPERATIONS.md)를 먼저 읽으세요. 검색 조건, 기록 보존, 회사 PC 준비, 커밋·푸시·배포 검증 절차와 요청 문구가 들어 있습니다.

## 기능
- 커리어 로드맵: 추천 방향, 강점과 준비할 역량, 첫 90일, 단계별 목표, 경험 증빙과 이직 판단 기준을 한 페이지로 확인
- 현재 후보 / 관심 공고 / 누적 공고 / 검색 조건
- 짧은 목록 → 요약 펼치기 → 상세 보기
- 직무 키워드 자동 분류, 검색·필터, 신규 강조·상단 정렬
- 관심 공고 스냅샷, 진행 상태, 메모, 조건 변경 이력
- 개인 기록 백업·가져오기, 기기별 출퇴근 출발지

## 운영
GitHub Pages는 main 브랜치 루트에서 배포합니다. 외부 라이브러리나 실행 서버가 필요 없습니다. 공고는 수동으로 검색·검증해 jobs.js에 갱신합니다. 페이지 재접속은 채용 사이트 검색을 실행하지 않습니다.

개인 메모와 출발지는 브라우저 localStorage에만 저장됩니다. 다른 기기·주소와 동기화되지 않습니다. 브라우저 데이터를 지우기 전 ‘검색 조건 → 내 기록 백업’을 이용하세요. 로컬 주소에서 Pages 주소로 이동할 때도 백업을 가져와야 합니다. 출발지는 각 브라우저에서 다시 설정합니다.

## 자료 갱신 규칙
1. 기존 공고를 삭제하지 않고 원문과 모집 상태를 재확인합니다. 검색 누락·접속 실패를 마감으로 단정하지 않습니다.
2. 공고 ID는 유지합니다. 삭제 확인 시 recruitment: '원문 삭제', 마감 확인 시 '마감', 확인 불가 시 '확인 필요'로 기록합니다. 조건 밖이면 outOfScope: true로 보관합니다.
3. JOB_UPDATE.id를 실제 조사 완료 시각(ISO 8601, +09:00)으로 변경하고 newIds와 changedIds를 이번 갱신 대상 ID로 설정합니다. 신규의 addedBatch에 같은 id를 기록합니다. 기존 공고 재발견은 신규가 아닙니다.
4. 다음 갱신마다 newIds/changedIds를 새로 작성합니다. 페이지 열람 시각이나 사용자의 첫 방문을 신규 판정에 사용하지 않습니다.
5. 공고 checkedAt, status와 근거를 기록하고 상단 자료 업데이트 시각 및 최근 검색 기록도 갱신합니다. 자료 갱신 없이 화면만 수정했다면 자료 시각을 바꾸지 않습니다.
6. 수치·급여·계약·근무시간을 검증한 후 반영합니다. 신규/변경 건수는 공고 단위입니다. 추측한 직원 수·통근시간은 입력하지 않습니다.
7. 집 주소, 연락처, 이력서, 메모, 개인 백업 파일은 저장소에 올리지 않습니다. 출처 링크는 각 공고에 유지합니다.

## 제한
키워드 기반 분류는 오분류 가능성이 있어 실제 업무를 확인해야 합니다. 공고 등록은 업체나 근무환경의 검증을 의미하지 않습니다. 일부 원문 재접속 제한과 직원 수·통근시간 미확인은 화면에 표시합니다.

## 급여 협의 탭
급여 협의·면접 후 결정·회사 내규·금액 미기재 공고는 급여만으로 제외하지 않고 다른 조건 검토 후 별도 수록합니다. salaryType은 negotiable/company-policy/undisclosed로 기록하고 pay에 원문 표현을 씁니다. 고정 저임금을 근거 없이 협의 가능으로 표시하지 않습니다. 마감·삭제·조건 제외는 누적/관심에서만 보관합니다.

## 특이사항·조사 기록
토요일·주말·시간·통근·계약 등 선호와 다른 조건은 specialNotes로 요약 카드와 복사 문구에 표시합니다. 특이사항 필터로 모아 볼 수 있습니다. 영업·외근·생산 중심 제외는 유지합니다. 조사 로그는 별도 조사 기록 탭에 보존합니다. 의료직 6개 전문 사이트를 추가 조사 대상으로 사용하며 접근 실패를 명시합니다.
